Cacti 4HTTP2SHELL — unpatched zero-day gives RCE through the guest account (public PoC)

Zero-day with a public PoC and no fix in the latest Cacti release.

Full details
1. Vulnerability details
No CVE yet (tracked as 4HTTP2SHELL / 4HTTP2ROOT) · Cacti Core 1.2.31 (latest) · unpatched · public PoC by researcher ek0ms savi0r · not reported exploited yet · not in KEV
2. Issue
A guest user can save a non-numeric value in a numeric display setting. That stored value bypasses validation and becomes a second-order SQL injection, which ends in a command run by the poller.
3. How it is exploited
Attacker uses the enabled guest account to store a crafted setting → stacked SQL statements change a poller database entry → the poller passes that entry to PHP popen() without sanitising it. Four HTTP requests in total.
4. Affected configurations
Cacti Core 1.2.31 and likely earlier releases, only when the guest account is enabled (disabled by default since 0.8.7).
5. Impact
Remote code execution as the Cacti server user, exposure of stored device credentials, pivoting into the network and silencing alerts by editing the poller table.

Recommendations

  • Disable the Cacti guest account now.
  • Restrict the Cacti web interface to admin networks / VPN.
  • Review poller entries for unexpected command values.
  • Apply the fix as soon as Cacti releases one.

Hex.pm (Elixir / Erlang registry) hacked via CVE-2026-129514 — passwords, 2FA and API keys may be exposed

Exploited RCE on the package registry itself; every hex.pm account is affected.

10.0EPSS 3.2% · 89% pct
Full details
1. Details
CVE-2026-129514 · CVSS 10.0 (v4) · deserialization of untrusted data · exploited 23 Nov (18:16–18:29 UTC, 69 requests to six servers) · disclosed 27 Nov · related fixes: Ash Framework CVE-2026-124283, db_connection CVE-2026-133555, flop CVE-2026-130411
2. Issue
The hex.pm request parser for Erlang-format bodies deserialized attacker data, letting an unauthenticated user run OS commands on the web servers.
3. How it is exploited
A crafted Erlang external term format request body sent to hex.pm → command execution on the web servers → server credentials readable.
4. Affected
All hex.pm account holders. Hex found no package tampering, database changes or persistent access.
5. Impact
Email addresses, password hashes, API key hashes, sessions, 2FA secrets and audit logs may have been read (reads are not logged). Hex rotated credentials and signing keys and logged everyone out.

Recommendations

  • Change hex.pm passwords and reset 2FA.
  • Rotate any Hex API keys used in CI.
  • Fetch packages only from repo.hex.pm, not third-party mirrors, until new Hex clients ship.
  • Watch for phishing emails pretending to be Hex.

Official Q-Dir and DesktopOK downloads trojanized to install a Python RAT

Supply-chain compromise of a vendor site: both new downloads and in-app updates were poisoned.

Full details
1. Details
AhnLab ASEC research · SoftwareOK website · Q-Dir 12.85 / 12.84 / 12.83 and DesktopOK 12.85 / 12.82 · active · how the installers were replaced is unknown · not attributed (Chinese-language comments in the code)
2. Issue
Installers on the official SoftwareOK site were swapped for versions that also install a Python remote access trojan.
3. How it is exploited
The installer runs the real program to avoid suspicion, downloads a Python RAT package, and keeps it running through a scheduled task that pretends to be Microsoft Edge. The RAT reports installed security products to its server.
4. Affected
Windows users who downloaded or auto-updated Q-Dir or DesktopOK to the listed versions.
5. Impact
Remote shell and Python code execution, file upload / download, screenshots and system information theft.

Recommendations

  • Check installed Q-Dir / DesktopOK versions and installer hashes.
  • Hunt for an Edge-named scheduled task running Python, and the files below.
  • Reimage affected machines — uninstalling may not remove the RAT.
  • Block the indicators below.

Switzerland confirms AI-agent attacks breached critical infrastructure operators

Follow-up to 26 Nov: the warning is now confirmed breaches, two of them at critical infrastructure.

Full details
1. Details
Swiss NCSC (BACS) · 5 confirmed attacks, 4 breached · 3 targeted critical infrastructure operators, 2 succeeded · agent frameworks named: ARTEX, CyberStrikeAI (CSIRT Italia also names PentAGI, DeepSeek Harness) · attackers not identified
2. Issue
Autonomous AI agents are running intrusions end to end against exposed systems, including electricity, drinking water and telecom suppliers.
3. How it is exploited
Agents scan for known unpatched flaws, run many attacks in parallel, chain vulnerabilities, misconfigurations and stolen credentials, and switch methods when blocked; their actions look like normal user or API traffic.
4. Affected
Internet-facing systems with unpatched known flaws; SMEs and critical infrastructure operators.
5. Impact
Footholds for further agent activity and downtime on some internet-facing services; no major disruption reported.

Recommendations

  • Patch critical flaws on internet-facing systems within 24 hours; exploited ones first.
  • Isolate internet-facing systems you cannot patch quickly.
  • Reduce exposure: geo-blocking, allow lists, authentication in front of services.
  • MFA or passkeys on every internet-reachable service; least privilege.
  • Alert on unusual request rates and data volumes; add honeytokens on high-value endpoints.

North Korea-linked PolinRider poisons 7,600+ GitHub repositories with a blockchain-controlled loader

Large, ongoing developer supply-chain campaign using stolen GitHub tokens to forge commits.

Full details
1. Details
Apiiro: 7,609 repos / 2,330 accounts · 2,040 repos poisoned 27 Oct – 6 Nov 2026 · sub-cluster alongside Contagious Interview · active since at least 2025
2. Issue
A hidden Python loader is planted in GitHub repositories (often a small utils package or conftest.py), with commits rewritten through stolen developer tokens so they keep the original author and date.
3. How it is exploited
Importing the code reads the latest transaction from an Ethereum wallet, decodes it as JavaScript and runs it with Node.js; a second wallet supplies the C2 address. Lures include fake recruiting sites and take-home tests (T1195.002, T1102).
4. Affected
Developers cloning or running poisoned repos; npm packages (itsa-*, @adminide-stack/*) and a VS Code extension were also used.
5. Impact
Infostealers and a remote-access tool persisting in VS Code, Cursor, Discord and GitHub Desktop; theft of environment secrets, browser passwords, cookies and wallets.

Recommendations

  • Run take-home tests and unknown repos only in a disposable VM.
  • Look for unexpected conftest.py / utils files that start Node.js.
  • Rotate GitHub tokens on any machine that ran a suspicious repo.
  • Block the indicators below.
